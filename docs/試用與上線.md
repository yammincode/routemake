# 試用版與正式版

| | 試用版 | 正式版 |
|---|---|---|
| 在哪裡 | 你的電腦（PowerShell 執行） | https://routemake.netlify.app |
| 程式來自 | GitHub 分支 `claude/happy-goldberg-szmqwa` | GitHub 分支 `main` |
| 更新方式 | 執行 `scripts\trial.ps1`，自動下載最新程式 | 你說「更新正式版」，Claude 把試用版合併到 `main` |
| 花 Netlify 額度 | 不花 | 每次約 15 credits |
| 資料庫 | 同一個 Supabase（試用時新增的資料正式版也看得到） | 同一個 Supabase |

## 第一次準備（只要做一次）

1. 安裝 Git 和 Node.js：打開 PowerShell，輸入
   ```powershell
   winget install Git.Git
   winget install OpenJS.NodeJS.LTS
   ```
   裝完**關掉 PowerShell 再重開**。
2. 下載程式（放在「文件」資料夾）：
   ```powershell
   cd $HOME\Documents
   git clone https://github.com/yammincode/routemake.git
   ```

## 每次試用

```powershell
cd $HOME\Documents\routemake
powershell -ExecutionPolicy Bypass -File scripts\trial.ps1
```

- 第一次會請你貼上 Supabase 的 publishable key（`sb_publishable_` 開頭）
- 看到「啟動試用版」後：
  - 電腦開 http://localhost:3000
  - 手機（同一個 Wi-Fi）開畫面上顯示的 `http://192.168.x.x:3000`
- Windows 跳出防火牆詢問時按「允許」
- 停止：在 PowerShell 視窗按 `Ctrl + C`

試用版沒有離線功能和「加到主畫面」（這兩個只有正式版有），其他功能都一樣。

## 更新正式版

試用確認沒問題後，跟 Claude 說「**更新正式版**」。Claude 會把目前的試用版合併到 `main`，Netlify 只會部署這一次。

### 版本號

入口頁 Logo 下方、「我的紀錄」頁最下面有一行小灰字（只有老闆登入後看得到）：

- 正式版：`v1.1・2026/10/03 更新`
- 自己電腦的試用版：`v1.1 試用版`

每次更新正式版的步驟：

1. 你說「更新正式版」
2. Claude 把 `lib/version.ts` 的版本號加 0.1（v1.1 → v1.2），日期改成上線當天
3. 跑完三項自動測試，全部通過才合併到 `main` 並推上去
4. Claude 回報「這次是 v1.2」和這版改了什麼
5. 你在手機上把 App 完全關掉再打開，看到 v1.2 就代表新版上去了（Netlify 部署約 2–3 分鐘；還是舊號碼就再關一次重開）
6. 照 Claude 列的「這次要請你在手機上確認的項目」逐項試一遍（完整清單在 [驗收清單](驗收清單.md)）

只有正式上線才換號，平常推到開發分支不換。

## 自動測試（給開發用）

每次修改後、更新正式版前都要全部通過：

```bash
npm run test:db     # 資料庫權限測試（需要本機 PostgreSQL）
npm run build
npm run test:e2e    # 手機操作測試（用模擬的 Supabase）
```

- 資料庫測試：`supabase/tests/`，用真的 PostgreSQL 驗證每個角色能做／不能做的事
- 手機操作測試：`tests/e2e/`，用 390px 手機尺寸的 Chromium 跑註冊登入、後台標路線、記錄與留言、我的紀錄與積分、離線、放大、LINE、防護標頭
- 在 Windows 跑手機操作測試前，先執行一次 `npx playwright-core install chromium`
